## 事实时间线

1. 从隔离登录页开始，自动登录、新建唯一项目、填写唯一名称和用户原始一句话，并完成一次首次构建提交。
2. Gateway 接受约 645 KiB 执行包，旧 Worker 却仍以 512 KiB 上限拒绝，暴露跨边界包大小策略不一致。Worker 修正为 512 KiB 告警、1 MiB 硬上限后恢复同一运行，没有重放创建或首次提交。
3. 第一个恢复观察调用遇到视觉 Provider 不响应。加入进程内硬超时并重启 Worker 后，第二个只观察 Job 在相同实体继续执行，没有重放 once-effect。

## 本轮证明的改进

- 推断配色、主题和运动风格已从硬验收降为建议项；只有用户明确要求的具体表现偏好才可保持为 must。
- 浏览器业务终态摘要只包含用户目标、must 功能/交互、required 验收和禁止结果，不再携带模型自行推断的色板、主题、动效或 should 项。
- 英文表现偏好检测使用单词边界，不再把 `required` 中的 `red` 子串误判为颜色要求。
- Worker 执行包采用 512 KiB 告警、1 MiB 硬上限，和 Gateway 保持一致。
- Browser 视觉 Provider 即使忽略 context 也会被 Harness 硬超时隔离，迟到结果不能修改当前观察。
- adaptive v2 的 App 运输期限从 `defer_after + 8 分钟` 扩到 `defer_after + 18 分钟`，由 Worker 完成业务观察窗口并负责终态。
- 产品返工文案已升级为“观测到的公开故障事实 + 单一修复目标”，例如明确指出“实际预览为空白或没有显示可交互的产品主界面”。

最后一项在本次运行启动后才实现并提交，因此三轮修复使用的仍是旧版简短目标文案。它不能被本次结果宣称为已通过真实验证，必须由下一次全新运行验证。
