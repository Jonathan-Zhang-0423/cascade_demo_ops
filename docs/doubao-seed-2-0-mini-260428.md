## 1. 模型定位

| 项目 | 内容 |
| --- | --- |
| 模型 ID | `doubao-seed-2-0-mini-260428` |
| 模型类型 | 轻量版深度思考大语言模型 |
| 所属系列 | 豆包 Seed 2.0 |
| 提供方 | 字节跳动 / 火山方舟生态 |
| 发布时间 | 2026 年 4 月 |
| 适用场景 | 低时延、高并发的通用交互、信息整理、简单代码辅助 |
| 方舟 Base URL | `https://ark.cn-beijing.volces.com/api/v3` |

### 1.1 能力

- 深度思考：支持先思考后回答；
- 文本生成：对话、写作、摘要、翻译；
- Function Calling：可调用自定义工具；
- 多模态理解：支持图片、音频输入理解，具体格式由接口约束；
- 结构化输出：支持 JSON 等结构化结果。

### 1.2 不能直接假设的能力

该模型本体是通用大语言模型，不能直接假设它提供：

- 原生录音文件 ASR 接口；
- 原生 TTS 音频生成接口；
- 原生降噪或音色转换接口。

项目中“语音识别”应通过火山方舟 LAS 的 Doubao-Seed-2.0 增强版算子；“语音合成”应通过豆包语音服务。两者要分别建 Provider 和请求/响应适配器。

## 2. 项目中的推荐用途

| 用途 | 入口 | 结果类型 | 是否可直接进入正式成片 |
| --- | --- | --- | --- |
| 音频理解、内容整理 | Seed 2.0 多模态输入 | 结构化文本/JSON | 否，需业务校验 |
| 自动字幕候选 | LAS 语音识别算子 | Transcript/Cue 候选 | 否，用户确认后进入 `CaptionCue` |
| AI 配音候选 | 豆包语音服务 | 音频素材候选 | 否，用户试听确认后进入 `NarrationClip` |
| 降噪、语速、混音 | Server 本地 FFmpeg/音频处理链 | 确定性音频素材 | 可以，须经过 Renderer 校验 |
| 音色转换 | 独立语音/变声服务 | 处理后音频候选 | 暂不自动入轨 |

模型输出不得修改业务步骤、替换真实产品录屏或证明业务执行成功。

## 3. LAS 语音识别能力

这是配套算子能力，不等同于模型本体的标准文本 Responses API。

| 能力 | 状态 | 对 Server 的意义 |
| --- | --- | --- |
| 录音文件识别 | 支持 | 支持 `wav/mp3/ogg/mp4/mov/mkv/flac` 等，视频自动提取音轨 |
| 中文识别 | 支持 | 首选中文 Demo 字幕候选 |
| 中英混合 | 支持 | 产品名、英文按钮可保留原文；纯英文建议单独评测 |
| 句子级时间戳 | 支持 | 可生成句级 `CaptionCue` |
| 词级时间戳 | 支持 | 可生成逐词对齐候选 |
| 标点恢复 | 支持 | 生成中文全角标点候选 |
| 热词 | 支持 | 配置产品名、人名、专业术语 |
| 置信度 | 支持 | 用于候选排序，不得单独作为业务真相 |
| 长音频 | 支持 | 单文件最大约 5 小时、5GB；实际配额以控制台为准 |
| 异步任务 | 支持 | Server 应保存任务状态、轮询/回调和失败原因 |
| 内置降噪 | 支持 | 作为识别前增强；仍建议保留原始录音和本地处理链 |

## 4. 豆包语音合成能力

TTS 通过豆包语音服务调用，不直接通过 `doubao-seed-2-0-mini-260428` 的通用 Responses API 调用。

### 4.1 音色和控制参数

- 30+ 中文音色，具体 `voice_id` 以控制台列表为准；
- 示例音色：
  - `zhfemalevvuranusbigtts`：Vivi 2.0；
  - `zhmalem191uranusbigtts`：云舟 2.0；
  - `zhfemalepeiqiuranus_bigtts`：佩奇猪 2.0；
- 语速：`0.5–2.0`，默认 `1.0`；
- 音调：`-12–12` 半音，默认 `0`；
- 音量：`0–100`，默认 `50`；
- 情感：如 `happy/angry/sad/calm`，实际可用值以音色支持矩阵为准；
- 支持 SSML，可控制停顿、重音、发音和数字读法。

### 4.2 输出约束

- 格式：`mp3/wav/pcm`；
- 采样率：`8000/16000/24000/48000 Hz`，默认 `24000 Hz`；
- 声道：默认单声道，也支持双声道；
- 单次文本上限：约 10000 字符；
- 单次生成时长：约 60 分钟；长文本应拆分后合成；
- 企业认证后可按调用量商用，具体授权和费用以账号合同为准。

Server 生成配音后应转码为 Renderer 的统一格式，建议 `48kHz、双声道、AAC/WAV 中间格式`，再写入 `NarrationClip`。

## 7. Server 接入边界

当前 [audio_model.go](../backend/internal/media/audio_model.go) 已提供 Provider-neutral 适配层：

- `dry_run`：记录规范化请求，不访问厂商；
- `real`：在厂商音频 API 文档确认前返回 `protocol_pending`；
- 禁止向云端发送 Server 本地路径；
- 原始音频只读保存；
- 模型输出登记为候选素材；
- 需要用户确认后才能写入 `CaptionCue` 或 `NarrationClip`；
- 请求和结果必须绑定输入/输出 SHA-256、模型 ID、版本和任务 ID。

## 8. 接入前必须补齐的官方资料

1. LAS 算子准确的 Endpoint、请求方式、文件上传方式和响应 JSON；
2. ASR 句级/词级时间戳字段名、置信度字段名和热词格式；
3. TTS Endpoint、`voice_id` 字段、SSML 字段和音频下载方式；
4. 同步/异步任务状态、轮询、回调、幂等键和错误码；
5. 限流、并发、超时、重试、费用和数据保留期；
6. 官方音色授权、声音克隆授权和商业使用限制；
7. `doubao-seed-2-0-mini-260428` 的音频理解输入格式和音频大小限制；
8. API Explorer 的脱敏成功响应和失败响应。
