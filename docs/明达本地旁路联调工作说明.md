# 明达本地旁路联调工作说明

## 1. 本次交付范围

本次联调使用的被测 Cascade 项目为：

```text
D:\备份Cascade-main\Cascade-main
```

交付内容分为三部分：

1. Cascade 被测产品源码和统一测试任务；
2. Ops Server/Browser Agent 的本地开发旁路及 video-worker；
3. 本说明、环境检查、启动、执行、结果检查和故障记录模板。

本地旁路只用于 development/loopback 联调，不代表正式 Exchange 验收，不得把旁路结果标记为生产或正式 Exchange 结果。

## 2. API 和账号要求

明达必须在自己的电脑上创建一个专用测试账号。账号密码由明达自行设置，只能在隔离的可见浏览器登录窗口中手动输入。

禁止将密码写入：

- 执行包、waiver、脚本或命令行参数；
- `.env`、日志、截图、录屏、字幕、StepResults 或测试报告；
- Git、网盘、群文件或工单。

Cascade 运行需要模型 API。交付时应提供“联调专用 API 配置”，而不是直接复制当前机器的完整 `.env`：

- 只保留本次测试实际需要的 provider/API 字段；
- 使用专用、低额度、可撤销的测试 API Key；
- 数据库地址、端口、路径和 `SESSION_SECRET` 使用明达本机值；
- API Key 通过单独安全渠道交付，不能写入公开说明或提交仓库；
- 联调结束后立即撤销或轮换该测试 Key。

如果必须交付包含密钥的配置文件，应使用加密压缩包，并通过另一渠道发送解压密码；不得把密钥和密码放在同一消息中。

## 3. Cascade 被测产品准备

在明达电脑上将项目复制或解压到本地目录，例如：

```text
D:\Cascade-Minda-Test\Cascade-main
```

不要依赖提供方电脑上的绝对路径。检查并按明达本机修改：

- `DATABASE_URL`：明达自己的 PostgreSQL；
- `PORT` 和 `APP_BASE_URL`：例如 `5000` 与 `http://127.0.0.1:5000`；
- `VIDEO_STORAGE_DIR`：明达本机可写目录；
- 实际使用的模型 API 配置。

初始化和启动：

```powershell
npm install --legacy-peer-deps
npm run db:push
npm run dev:start
```

启动后先人工确认 `/app` 可以打开、测试账号可以登录，并手动创建一个简单项目确认模型构建 API 可用。

## 4. Server 本地旁路准备

旁路运行必须明确标记：

```text
dev_test_only=true
not_for_exchange_upload=true
formal_exchange=false
loopback_only=true
```

Server 旁路只能对事先明确列出的节点签发限时、节点级 waiver。waiver 必须绑定 package ID、bundle hash、plan hash、node/stage、interaction index、action type 和 semantic ID。

旁路不得：

- 修改原始 App 执行包或其哈希；
- 绕过正式 Exchange 校验；
- 新增 App 没有声明的业务动作、输入、完成条件或字幕；
- 放宽域名、来源、路由、禁止页面或破坏性操作边界。

明达需记录：Server commit/version、Go/Node/Chromium/FFmpeg 版本、旁路启动参数及所有 waiver ID。

## 5. 测试流程

1. 由 App 按正式规则生成原始 `browser-agent-outline-v1` 执行包。
2. 保存原始包、bundle hash、plan hash、正式校验结果和阻断报告。
3. 如正式校验阻断，仅由 Server 旁路对明确批准项签发 waiver。
4. 在隔离可见浏览器中手动登录 Cascade；Server 不读取或注入密码。
5. Server 按原始 Outline 执行真实页面。
6. 采集原始录屏、阶段截图、StepResults、Validation Reports、阶段事件、脱敏日志和浏览器 trace。
7. 执行结束后渲染 MP4，生成本地测试结果包和 SHA-256 checksum。
8. 结果包下载后核对 checksum，并记录 ACK；结果包仍保持本地测试标记，不得上传正式 Exchange。

## 6. 统一业务任务和通过标准

使用随包提供的 `统一测试任务.md`。目标是完成贪吃蛇游戏构建，并确认：

- 最终页面已离开排队/生成中/构建中状态且无可见错误；
- 页面出现可辨认的贪吃蛇游戏；
- 存在界面颜色自定义入口；
- 存在三种可区分的难度模式；
- 页面稳定显示，可采集完成截图和真实 StepResults；
- 最终 MP4 包含完整动作和约定的中文字幕。

只满足流程无报错而未满足业务结果时，必须记录为“业务结果未满足”。

- [ ] 原始包字段和哈希可保存并复核；

- [ ] 结果包包含录屏、截图、StepResults、Validation、日志和 checksum；
